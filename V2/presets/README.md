# 本地预设（presets/index.js）

本目录只有一个文件：**`index.js`（预设清单，可直接手工编辑）**。启动时会自动加载，无需任何构建步骤。

## 怎么添加预设

1. 在应用里调好参数 → 点「预设」面板的**导出**，得到一份预设 JSON 文件；
2. 用文本编辑器打开 `index.js`，把这份 JSON 的内容**原样**粘成 `files` 下的一个条目（JSON 是 JS
   对象字面量的子集：双引号、`null`、`true/false` 都照原样保留，不需要改写）：

```js
window.KICON_LOCAL_PRESETS = {
  files: {
    "我的预设.json": { "type": "kicon-preset", "version": "2.21", "name": "我的预设",
                       "time": 0, "snap": { …导出文件里的 snap 原文… } },
  }
};
```

3. 保存后**刷新页面**即出现在预设网格中（可直接点击应用）。

## 规则与注意

- 键（引号里的名字）只用于标识与去重：预设名优先取内容里的 `name` 字段，没有 `name` 才用键名。
- 每个条目必须是**单个对象字面量**；条目之间用逗号分隔；**最后一条后面不要留逗号**。
- 整份文件必须能被浏览器正常解析：**一处语法错 → 一条预设都加载不出来**
  （应用本身仍会正常启动，控制台会给出 `[本地预设]` 的提示，据此排查）。
- 含图片的预设（`snap.rows[].image.data` 是 dataURL）会非常长，粘贴时不要截断。
- 文件里的 `snap` 缺失字段会用默认值补齐、多余字段会被忽略并在控制台列出；
  内嵌的图片数据会自动注册进会话图片仓库（预设只保留引用）。
- 文件顶部的示例条目就是「导出预设」的完整产物，可直接复制改造，也可以整条删除。

## 为什么用 JS 而不是逐个 json 文件

浏览器**禁止 `file://` 页面用脚本读取本地文件**（`fetch`/XHR 都被拦），而本项目要求"双击
`index.html` 即可用"。`<script>` 加载则不受此限制，因此把预设放进 `index.js`：

- 双击打开（`file://`）与静态服务器部署（`http(s)`）**行为完全一致**；
- 不需要任何生成/构建步骤，改完刷新即可；
- 代价：没有"每个预设一个 json 文件"的目录结构，且单个条目的语法错误会影响整份文件
  （逐条解析失败仍会跳过并告警，不影响其余条目）。
