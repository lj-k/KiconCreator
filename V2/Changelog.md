## [V2.26] - 2026-09-22

### 修正：边界形状只作用于"填充之间的分界线"，填充外缘必须贴合形状

**用户原文**："不对，如果不包含形状外框的时候，应该只调节填充之间的一条直线。例如双色填充时候，设置为sin，应当是以形状中心点为原点，两个色之间的直线分界线为x轴，绘制一条sin线，作为新的填充分界线。"

**问题（V2.24/V2.25 的行为）**：边界形状把色块多边形的**四条边都**按波形位移了，包括贴着形状轮廓的"填充外边界"（矩阵的最左/最右竖边、最上层上边、最下层下边；饼图的最外环外弧、最内环内弧、单色层那条半径）。由于形状裁切仍是原轮廓，波形向内的一侧就在轮廓内侧留下**未着色空隙**——栅格实测：双色 + sin(A=20%、ω=1) 时，矩阵布局露出 **12.99%**、饼图布局露出 **20.19%** 的形状面积。

**修正**（fillLayout.js V0.07）：
- 矩阵：`straightV`/`straightH` 让**外边界**（最左/最右竖边、最上层上边、最下层下边）保持直线，只有**内部接缝**（同层相邻色块之间、层与层之间）走 `edgeCurveV/H`；
- 饼图：`edgeCurveRing(..., plain)` 让**最外环外弧 / 最内环内弧**保持正圆（`r0=0` 的"环"在 φ/k 非 0 时会被推成小圆，同样必须 plain）；`edgeCurveRay(..., plain)` 让**单色层那条半径**（不成缝）保持直边；
- 过渡带本来只画在内部接缝上，语义不变；
- 顺带：边界形状为"直线"时 `edgeSteps` 直接返回 2 段，不再为直边白采样上百个点。

**修正后的语义（与用户描述一致）**：以双色矩阵为例——以形状中心为原点、把两色之间的那条直线分界线当作 x 轴，在其上画一条 `y = A·sin(2π·ω·x/S + φ) + k` 作为新的分界线；外侧两条边、上下两条边仍是直线，填充始终铺满形状。

## [V2.25] - 2026-09-22

### 填充边界新增"是否包含形状外框"（默认不包含）

**用户原文**："填充边界标签中，增加一个选项，是否包含形状外框。默认不包含，只调节内部填充之间的边界"

- **参数**（schema.js V0.09）：`FILL_PARAM_DEFS` 新增 `edge.frame`（`type: 'bool'`，默认 `false`）。它随 `fillParams` 一起入快照/预设、可撤销。
- **面板**（panes.js V0.11）：填充边界 pane 在参数行之后新增复选行「包含形状外框（默认只调节内部填充之间的边界）」，绑定 `data-pkey="edge.frame"`。
- **几何**（fillLayout.js V0.06 的 `edgeFramePoints`）：关闭时轮廓**原样返回**（零开销、零视觉变化）；开启时把轮廓本身沿**外法向**按波形位移，因此框线、内容裁切、填充覆盖范围与外接框一起变形。闭合轮廓与"分界线"不同，实现上做了三件事：① 先按 ~2px 重采样（形状自带的点远稀于一个波形周期）；② 周期数 / 齿数**取整**后再铺波，保证 `d(0)=d(L)`（否则起点有一道台阶）；③ 位置参数取**沿轮廓的弧长**，原点为"最靠近正上方（−90°）的点"（与饼图环分界同一约定）。
- **接线**（bgshape.js V0.05）：`shapeOutline` 末尾 `return typeof edgeFramePoints === 'function' ? edgeFramePoints(out, S) : out;` —— 一处接入，框线/裁切/填充/填满求解全部跟随。
- 顺带修正：`normalizeFillParams` 之前只处理 `select` 与数值两类，bool 型键会被数值分支的 min/max 夹取丢掉（表现为勾选后一刷新又变回关闭）→ 现在 `type: 'bool'` 按真值原样保留。
- 顺带改进：引导器可选资源（`presets/index.js`）加载失败的提示原为"可选资源缺失"，而**语法错**也会走同一分支（易误判为"文件不见了"）→ 措辞改为"未生效（文件缺失，或存在语法错误导致无法解析）"，并提示检查该文件能否被浏览器解析。

## [V2.24] - 2026-09-22

### 完成填充边界功能（需求 2.3 标签"填充边界"）

**用户原文**："完成填充边界功能"

**需求原文要点**（doc/需求文档.md L105-109）：过渡宽度（默认 0 = 无过渡）；边界形状 直线/sin/tan/锯齿（"tan 和 sin 的圆点均为中心点"）；选择 sin/tan 时可配置 `y=Asin(ωx+φ)+k`、`y=Atan(ωx+φ)+k` 的 A、ω、φ、k（参数要有合法范围限制、渲染做截断保护、超出画布大小 10 倍后截断）；锯齿可设置 A 高度、ω 宽度，原点以形状中心为基准；过渡样式 单色/渐变/加深/变浅/透明。

**实现**：

- **参数注册**（schema.js V0.08）：`FILL_PARAM_DEFS` 新增 8 键——`edge.width`（0~100%，默认 0）、`edge.shape`（直线，默认）、`edge.A`（0~50%，默认 10）、`edge.W`（ω，0.1~10 步进 0.1，默认 2 = 横跨画布的周期数）、`edge.phi`（−180~180°，默认 0）、`edge.k`（−50~50%，默认 0）、`edge.tooth`（锯齿 ω 齿宽 1~100%，默认 12）、`edge.style`（默认 渐变）。全部随 `fillParams` 入快照/预设。
- **边界位移**（fillLayout.js V0.05）：`edgeOffset(t, S, cfg)` —— `t` 为边界上的位置参数、**原点在形状中心**（矩阵竖向分界取局部 y、横向取局部 x；饼图径向分界取半径 r、环分界取弧长）；`d = A·f(2π·ω·t/S+φ) + k`（f = sin/tan）；锯齿为三角波（t=0 齿峰、半齿齿谷）。**安全保护**：ω 下限 0.05、tan 近渐近线先按 A 限幅、最终位移 `clampEdge` 截断到 ±10×画布且永不 NaN；饼图径向分界在靠圆心的 1/4 画布内把振幅线性收敛到 0（否则 r→0 时角偏移发散、扇区互穿露底）。
- **色块绘制改为采样多边形**：`edgeCurveV/H/Ray/Ring` 把分界线采样成曲线，`cellPolygon`/`sectorPolygon` 拼闭合区域（四角取两条边界候选点的中点 → 相邻色块共用角点、无缝）；采样密度 `edgeSteps(span)` ≈ 2px 一段（24~240 段）。
- **过渡带**（`paintEdgeBand`）：在所有色块之后沿**同一条采样曲线**描边，`lineWidth` = 过渡宽度；单色 = 两端色中值平涂；渐变 = 沿带法向两端色渐变（闭合环用径向渐变）；加深/变浅 = 中值色明度减/加；透明 = `destination-out` 擦成透明缝。带色取自边界两侧的真实色块色值。
- **面板**（panes.js V0.10）：`fillEdgePaneHTML` + `edgeShapeParamsHTML` —— 过渡宽度行 + 边界形状芯片 + 随形状增减的参数行（直线 0 / sin·tan 4 行 A 振幅·ω 频率·φ 相位·k 偏移 / 锯齿 2 行 A 高度·ω 齿宽，均带滑块+数字框+重置）+ 过渡样式芯片；芯片逐片带 `data-val`，由新增的 `bindFillParamChips`（fillLayout.js）绑定，形状变化重渲染本模块。
- **清理**：删除 UI-only 的 `currentEdgeShape`（state.js / history.js 快照）与预留的 `buildEdgeParams`（builders.js），边界形状改存 `fillParams['edge.shape']`（可撤销、随预设往返）。用户旧预设里的 `currentEdgeShape` 字段会被 loader 记为"多余字段"（仅诊断，不影响加载）。

**偏离需求说明**：需求 2.3 提到边界参数应有"联动"按钮——这几行属全局唯一的背景类参数（与形状与外框参数一致），本项目不提供"逐行联动"链条（见 ARCHITECTURE 4.11/4.14）。

## [V2.23] - 2026-09-22

### 1. 修复：形状与外框、填充数量与布局模块拖动滑块时，数字框与蓝色进度条不跟随（用户反馈）

**用户原文**："修复形状与外框模块、填充数量与布局模块中，所有参数滑块调节时候，输入框中的参数值、滑块的蓝色条不跟随变化的问题。"

**定位**：`interactions.js` 的通用滑块循环里，`upd()`（写数字框 + 写 `--fill` 蓝色进度）只在**绑定当时**调用一次；`input` 事件只写状态与重绘画布，因此拖动过程中数字框与蓝色条停在旧值，松手（`change`）后仍不刷新——只有数字框输入/点重置才会走到 `upd()`。HSL 滑轨（`data-hsl`）自带 `upd()` 所以不受影响，这也解释了为何只在部分模块被察觉。

**修复**：`input` 事件先调 `upd()` 再写状态（interactions.js V0.06）。此后滑块的三个显示入口（手柄位置、蓝色进度、数字框）在拖动、输入、重置、程序化回写四条路径上一致。

### 2. 修复：「填满绘图区域」应取"不超出画布"前提下的尺寸最大值（用户反馈）

### 实现过程中发现并修正的问题（同版本内修复，勘误汇总）

1. **饼图"层间比例"误用矩阵的轴向映射**：曾用 `fillBoundaries`（−half…+half）算环半径，导致比例 50% 时分界线落在 R 之外、外层整片消失。→ 新增 `fillRadii`（0…R 半径映射）；尺寸极值语义修正为"该层消失、其余层铺满整个形状"。
2. **饼图"层内比例"的默认与"均分"不是均分**：角分界线首尾相接（k 条分界定义 k 个扇区），却沿用了矩阵"两端留边"的 `fillEqualRatios(k) = (i+1)/(k+1)`，默认与均分都会给出"k−1 个等宽扇区 + 1 个双倍宽扇区"。→ 新增 `fillEqualAngles(k) = i/k×100`（首项 0）与 `fillEqualInRatios(model)`，均分按钮按布局选择公式（需求 2.3"默认也是均分"）。
3. **布局形式芯片点击不切换布局**：`inlineChips` 生成的芯片没有逐片取值属性，而绑定读 `chip.dataset.layout`（恒为 `undefined`），点击只高亮不改状态。→ `inlineChips` 支持 `opts.values` 输出 `data-val`，绑定读 `dataset.val`（缺属性时退回芯片文字）。
4. **切换布局形式产生重合分界**：矩阵（k−1 条竖线）⇄ 饼图（k 条角分界）语义不同，直接沿用旧数组会补出一条重复分界，出现"一个 0 宽扇区 + 一个双宽扇区"。→ 新增 `convertInRatios` 按"各段跨度"换算（矩阵→饼图前补 0；饼图→矩阵去掉首条并减去它），两式互逆、参数不丢（需求 2.1）。

## [V2.11] - 2026-09-20

### 修复：切换标签导致无关模块闪烁 + 标签组重算导致标签跳位（用户反馈）

**问题原因（两条同源）**：任何内容变化都会触发"全量重建"。
1. `rerenderModule()` 先用 `computeTabLayout(heights, 0)`（可用空间按 0 计）算出**塌缩分组**渲染一次，随后 `refreshLayout()` 再按真实空间展开一次 → 被改模块"先塌后展"地跳一下。
2. `refreshLayout()` → `relayoutAllModules()` 对**每一列的所有 tab 模块**执行 `container.innerHTML = …` 整体重建；预设模块还会连带 `renderPresets()`/`renderHistory()` 重画缩略图 → **无关模块全部闪一下**。
3. 同一函数按 pane 自然高度重算分组：样式模块「单色 → 渐变」使颜色 pane 变高 → 高度数组变化 → 分组结果变化 → 颜色标签可能被划到另一个标签组（从上方跑到下方），用户找不到原标签。

**修复**：
- **两级刷新入口**（layout.js V0.03）：
  - `refreshLayout()`（**视口级**）— 重算标签组拆分/合并。仅在 resize、orientationchange、布局模式切换、字体就绪、合并标签切换、放大预览、初始化、ResizeObserver 时调用；
  - `refreshLayoutKeepGroups()`（**内容级**）— 不改动标签组结构（标签保持原位），仅更新顶栏高度、合并标签定位、预览高度与浮动状态。用于切换行、改参数、撤销、行数/填充数量变化。
- **结构签名跳过无谓重建**（tabs.js V0.03）：`groupsSignature()` 生成"分组划分 + 标签启用态"签名（**故意不含激活态**——激活由点击直接切类名，不构成结构变化）；`renderTabGroupsFromGroups(…, forceRebuild)` 在结构未变且非强制时直接返回，**完全不触碰 DOM**。视口变化但分组结果不变时也不再重建（resize 也不再闪）。
- **保持标签原位**（tabs.js `readCurrentGroups()`）：`rerenderModule()` 改为沿用当前 DOM 中的分组（`data-group` 解析为索引数组），不再用 `computeTabLayout(heights, 0)` 塌缩；DOM 标签集合与预期不符（如新增/删除标签）时才回退重算。← 对应"标签组内标签尺寸改变应保持标签原位"的要求。
- **顺带修正**：填充数量切换与撤销恢复原先依赖"列全量重建"的副作用来刷新「布局/填充边界」pane（单色 ⇄ 多色文案与参数不同）；改为显式 `rerenderModule('fill')`（topbar.js / history.js V0.05），否则轻量刷新下该 pane 会显示过期内容。
