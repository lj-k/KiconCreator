## [V2.16] - 2026-09-21

### 修复：图片"剪裁 → 导出 → 重新导入"后分辨率与裁切观感不一致（用户反馈）

**用户原文**："图片剪裁，导出然后重新导入后，分辨率和剪裁效果好像与导出前的不太一样，请测试定位原因，然后分析修复。"

**定位（先测后改，量化）**——新建往返测试 `/tmp/test_crop_roundtrip_v216.js`，用 1024×768 原图 + 1:1 比例 + zoom 2.5 + 偏移 (0.3, -0.2) 复现：

| 观测点 | 修复前实测 | 说明 |
|---|---|---|
| 裁切窗口 | 307.2×307.2 像素 | 裁剪几何本身正确（比例×最大内接矩形×zoom×平移） |
| cropped 导出实际像素 | **256×256**（像素仅剩 69.4%） | 导出编码默认上限写死 256 → 窗口被强制降采样 |
| 再导入后显示 | 256×256 位图放大到 512/1024 画布 | 观感即"分辨率不一样/变模糊" |
| 编码压缩 | WebP q0.82（整图 q0.9），失败还退 JPEG | 有损压缩叠加一层损失；JPEG 分支会丢透明通道 |
| dataURL 入库 | 不降采样（文件入库却降采样到 1024） | 两条入库路径标准不一：外部大图入库后再导出被降到 1024，**往返一次掉一档** |

**结论**：裁剪几何（等比量）本身与分辨率无关，也不存在二次裁切；用户感到的"不一致"来自**像素被降采样 + 有损压缩**，以及两条入库路径分辨率标准不统一造成的多轮累积劣化。

**修复**（images.js V0.03）：
1. **编码上限对齐入库上限**：`imgCropDataURL` 默认上限由 256 改为 `IMG_MAX_EDGE`（1024）——窗口 ≤ 上限时 `k = 1`，**不再缩放，窗口像素即导出分辨率**。
2. **编码改为"无损优先"**：新增 `IMG_PNG_MAX`（PNG dataURL 体量上限 256KB）与 `imgEncodeCanvas(c, quality)`——
   优先 PNG 无损（图标类平涂 + 透明通道体积可控）；PNG 超体量（照片类）才退 **WebP q0.95 近无损**；**不再用 JPEG 兜底**（JPEG 无 Alpha，会把透明背景压黑底）。
   `imgFullDataURL` 同步改走同一编码函数。
3. **统一入库分辨率标准**：`imgLoadData`（预设导入 / 解码回退）超长边按 `IMG_MAX_EDGE` 画布等高降采样，与 `imgLoadFile` 的 `imgNormalize` 同标准，杜绝"入库 2048 → 导出 1024 → 再入库 2048"式的逐轮劣化。

**几何不变**：`original` 模式（整图 + 保留裁剪参数）与 `cropped` 模式（窗口像素 + 清零参数）的既有语义与二次裁切防护不变。

## [V2.15] - 2026-09-21

### 修复：导出预设导出了整张预设列表（用户反馈，需求 2.1）

**需求原文**："导出预设是导出**当前的参数**为预设，并非将预设列表中的所有预设全部导出。导入也是，只是导入一个独立的预设，但可以批量导入 N 个 json 文件为 N 个独立的预设。"

**改动**：
1. **导出**（presets.js V0.04）：由「导出 `PRESETS` 全部条目（数组）」改为「导出**当前参数**这一条预设」——
   产出单个 JSON 对象 `{ type:'kicon-preset', version, name, time, snap }`，文件名 `KIcon-preset-{内容}-{时间}.json`；

   文件内为数组时（早期整表导出）仍按多条导入并在控制台/差异中说明，避免丢数据。
3. **UI 提示**（panes.js V0.04）：导入/导出按钮补 `title`，分别说明"一个 json 文件 = 一条预设，可批量选文件"与
   "把当前参数导出为一条预设，不导出预设列表"。
4. **顺带整理**：抽出 `timeStamp()`（exports.js V0.07），`buildFileName` 与预设导出文件名共用同一时间戳实现。

## [V2.14] - 2026-09-20

### 修复：导出预设后再导入，图片被二次裁切（用户反馈）

**现象**：加载图片 → 剪裁一块 → 导出预设 → 刷新页面 → 导入该预设，画面与导出前不一致。

**原因**：导出时把「**剪裁后的像素**」和「**原剪裁参数**」一起写进了 JSON。导入后新图（已经是裁切后的画面）
又套用同一组参数再裁一次，等于裁了两遍。

**修复（按需求：导出时询问保存原始还是剪裁后的图片）**：
1. **导出前提示**（`askImageExportMode`，imagePane.js V0.02）：只要本次导出/下载/复制涉及**已剪裁**的图片，
   就弹出对话框并列出受影响的图片（行号 + 文件名），三选一：
   - **保留原始图片**：导出整张原图 + 保留剪裁参数 → 导入后与当前效果完全一致（体积较大）；
   - **保存剪裁后图片**：只导出剪裁后的画面 + **清零剪裁参数** → 体积小，但导入后不可再调整裁切范围；
   - **取消**：不产出文件（ESC / 点击遮罩同效）。
2. **三条出口统一**（`snapForExport`，presets.js V0.03）：预设导出、下载 pane 的 JSON（需求 2.34 "json = 导出预设"）、
   复制 JSON 全部改走同一序列化函数——原先"下载 JSON / 复制 JSON"直接序列化会话快照，导出的是**本会话的图片 id**，
   外部打开必然"图片缺失"。现在统一为：图片 → dataURL（按所选模式）+ 去掉仓库 id。
   - `original`：`imgFullDataURL`（整图重编码，≤1024、WebP）；`cropped`：`imgCropDataURL`（裁切窗口）+ `crop` 复位；
   - 纯函数：所有改动落在深拷贝上，**不改动会话状态**（编辑中的裁切参数不受导出选择影响）。
3. **裁切判定**（`imgIsCropped`，images.js V0.02）：用"实际裁剪窗口 vs 整图矩形"比对，而不是只看参数——
   例如 zoom=1 且比例为原图时，平移参数不产生任何实际裁切，不会误报提示。
4. **顺带修正**：`makeImageState` 的默认裁剪比例由 `1:1` 改为 `原图`（schema.js V0.04）——原先外部预设一旦缺少
   `crop` 字段，非方形图会被静默裁成方形。

### 版本号同步
- `index.html` `.ver`、`snapshotState().version`（'2.14'）、`exportHTML` 注释、欢迎 toast → V2.14；根导航页徽标同步（根 Changelog V0.08）。

## [V2.13] - 2026-09-20

### 图片模式（需求 2.8 / 3.4 / 3.6 + 六.1）

**新增 2 个模块**：`js/images.js`（会话图片仓库）、`js/imagePane.js`（图片面板与剪裁器），已按序接入 `index.html` 引导器（utils 之后、content 之后）。

1. **会话图片仓库**（需求 六.1）：`ImageRepo` 全程序只保存一份图片数据（解码位图 + 元数据）；行、预设、下载历史、撤销快照**只存 `image.id`**。
   - 引用计数按"引用键"登记：行 `row:i`、预设 `preset:<uid>`、历史 `hist:`、撤销栈 `undo:`；无引用后**延迟 4s 释放**，期内再次引用即取消释放；
   - 快照/预设对象的引用键存 `WeakMap`，不写入对象本身（JSON 导出保持干净）；
   - 撤销栈 FIFO 淘汰与被覆盖的重做链快照均注销引用（需求 四.2）；下载历史超限淘汰、预设/历史删除同样注销；
   - `imgSyncRowRefs()` 在恢复快照后把行引用与 `rows` 对齐——**切换行与模式不解除引用**（需求 2.8）。
2. **上传**（需求 2.8）：文件选择 → 进度条 → `createImageBitmap` 解码（**动图取首帧**）→ 入库；大于 1MB 提醒可能卡顿；失败 toast 含具体原因（非图片/读取失败/解码失败）；超长边自动降采样到 1024（内存保护）；更换图片时解除该行对旧图片的引用。
3. **渲染**（`canvas.js drawRowImage`）：按 `imgCropRect` 裁剪窗口绘制到内容盒，三种内容模式**共用同一条变换管线**（大小/角度/水平垂直拉伸/偏移/阴影，需求 3.5）；`image.whiteTransparent` 打开时走 `imgChroma` 色度键（按图片缓存，带过渡避免锯齿）。
4. **面板与剪裁器**（需求 3.6）：剪裁后预览常显；剪裁器含 缩放滑块、快速比例（原图/1:1/4:3/16:9/3:4）、预览内拖拽移动、滚轮缩放、双击复位；拖动/滚轮过程实时重绘不入栈，**松开后才 `commitHistory()`**（需求 四.2）。
5. **行数据**：`rows[i].image = { id, name, w, h, crop{aspect,zoom,ox,oy} }`，随 `normalizeRow` 规范化与深拷贝；文本/FA 模式下该字段原样保留（需求 四.1 例2）。标签标题显示原图片名。
6. **预设往返**（需求 2.1）：导出把图片按"**可见裁切部分**"渲染并量化为 WebP dataURL 随 JSON 导出，仓库 id 不导出；导入把图片数据注册进仓库后改为引用，并**先作废旧 id**（避免命中同会话的另一张图）；解码失败或数据缺失占位"图片缺失"；支持一次选择多个 json 文件。
7. **缩略图按真实样式渲染**（需求 2.1/2.2）：新增 `renderSnapshotThumb`（临时切换渲染目标与状态后复用 `drawIcon`，同步执行并在 `finally` 恢复），预设网格与下载历史缩略图不再使用占位渐变色块。
8. **文件名**（需求 2.35）：改为**所有可见行**拼接——文本用文本、FA 用 FA 代号、图片用原图片名（去扩展名）。

## [V2.11] - 2026-09-20

### 修复：切换标签导致无关模块闪烁 + 标签组重算导致标签跳位（用户反馈）

**问题原因（两条同源）**：任何内容变化都会触发"全量重建"。
1. `rerenderModule()` 先用 `computeTabLayout(heights, 0)`（可用空间按 0 计）算出**塌缩分组**渲染一次，随后 `refreshLayout()` 再按真实空间展开一次 → 被改模块"先塌后展"地跳一下。
2. `refreshLayout()` → `relayoutAllModules()` 对**每一列的所有 tab 模块**执行 `container.innerHTML = …` 整体重建；预设模块还会连带 `renderPresets()`/`renderHistory()` 重画缩略图 → **无关模块全部闪一下**。
3. 同一函数按 pane 自然高度重算分组：样式模块「单色 → 渐变」使颜色 pane 变高 → 高度数组变化 → 分组结果变化 → 颜色标签可能被划到另一个标签组（从上方跑到下方），用户找不到原标签。

**修复**：
- **两级刷新入口**（layout.js V0.03）：
  - `refreshLayout()`（**视口级**）— 重算标签组拆分/合并。仅在 resize、orientationchange、布局模式切换、字体就绪、合并标签切换、放大预览、初始化、ResizeObserver 时调用；
  - `refreshLayoutKeepGroups()`（**内容级**）— 不改动标签组结构（标签保持原位），仅更新顶栏高度、合并标签定位、预览高度与浮动状态。用于切换行、改参数、撤销、行数/填充数量变化。
- **结构签名跳过无谓重建**（tabs.js V0.03）：`groupsSignature()` 生成"分组划分 + 标签启用态"签名（**故意不含激活态**——激活由点击直接切类名，不构成结构变化）；`renderTabGroupsFromGroups(…, forceRebuild)` 在结构未变且非强制时直接返回，**完全不触碰 DOM**。视口变化但分组结果不变时也不再重建（resize 也不再闪）。
- **保持标签原位**（tabs.js `readCurrentGroups()`）：`rerenderModule()` 改为沿用当前 DOM 中的分组（`data-group` 解析为索引数组），不再用 `computeTabLayout(heights, 0)` 塌缩；DOM 标签集合与预期不符（如新增/删除标签）时才回退重算。← 对应"标签组内标签尺寸改变应保持标签原位"的要求。
- **顺带修正**：填充数量切换与撤销恢复原先依赖"列全量重建"的副作用来刷新「布局/填充边界」pane（单色 ⇄ 多色文案与参数不同）；改为显式 `rerenderModule('fill')`（topbar.js / history.js V0.05），否则轻量刷新下该 pane 会显示过期内容。

  - `readCurrentGroups`：正确解析 `[[1],[0,2]]`；DOM 含未知标签 → `null`；DOM 未覆盖全部标签 → `null`；
